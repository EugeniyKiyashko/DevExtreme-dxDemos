dxSpeedDialAction: the 16px right offset is swallowed by the scrollbar

The FAB is placed against the window, 16px from its right edge. It ends up flush against the scrollbar instead, and a window resize puts it right. Two independent causes were found, both fixed here.

1. The window's size was taken as innerWidth. calculatePosition in __internal/common/core/animation/m_position.ts used innerWidth whenever innerWidth > outerWidth. innerWidth includes the classic scrollbar, documentElement.clientWidth does not, so the whole offset is spent on the scrollbar. That branch is reached on a zoomed out page, where the viewport in CSS pixels is wider than the window, and before the first frame is painted, where Chrome still reports outerWidth as 0 - which is exactly when widgets are created on document ready. The window is now always measured by its client size.

2. The overlay never learned that the scrollbar had appeared. An overlay re-renders its geometry on a window resize, and the window resize event is not raised when only a scrollbar appears or disappears. A FAB created while the page still fits the screen keeps its old coordinate once content arrives and the scrollbar shows up. This one reproduces in every browser.
